Wake your session on CI failures and merge conflicts — no foreground polling, no comment-channel injection.

> [!IMPORTANT]
> **A green draft PR no longer reports `ready`.** It reports the new terminal **`ready_draft`** event, whose next action is to review the draft and run `gh pr ready`, then **relaunch the watcher**. Jobs gated on the draft flag report as skipping on a draft, and skipping counts as passing, so they first run after the undraft, and nothing nudges you on `gh pr ready`. Under `PR_SENTINEL_WATCH_UNTIL=closed` the notice is `ready_draft_watching`. If anything matches on `PR-SENTINEL EVENT: ready` to hand a PR back for merge review, a draft no longer reaches it (#188).

> [!WARNING]
> **Through 0.12.0, a watcher that exited before a Claude Code restart still counted as live after it.** A resumed session's transcript does not carry the harness record that closes a launch, so the PostToolUse nudge said the PR was watched, and the PreToolUse guard refused the PR's only real watcher as a duplicate. The PR stayed unwatched until the session used `PR_SENTINEL_OVERRIDE`. Separately, a heredoc or quoted string that only mentioned `gh pr merge <N>` marked that PR concluded, so the Stop hook let the turn end with it open and unwatched, and said nothing (#164, #168).

## Highlights

**[The overlap check on `gh pr create` refuses far less work that git would merge](https://github.com/karlkfi/claude-pr-sentinel/blob/v0.13.0/README.md#overlapping-pull-requests).** Edits within six lines of an open PR's used to be enough to deny. Now, where that PR's head commit is in your clone and git is 2.38 or later, `git merge-tree` trial-merges it with your branch, and the deny stands only on a conflict your fork point does not also have, or on an identical edit made twice. When the head is not local, the line ranges predict the merge by git's own rule: the create is denied only where the two sides' changed lines touch with no unchanged line between them, and the denial says it was not trial-merged and names the `git fetch` after which a re-run decides it (#176, #193). Nine more fixes remove specific wrong refusals. The check now judges the branch the create opens (its `--head`, or a `git checkout` earlier in the same command), not the one checked out (#161), and the checkout a literal `cd` earlier in the same command lands in (#191). It compares a `--repo` create against that repository's open PRs (#173). It recognises a stack opened against the default branch by the parent's head commit being in your branch (#174). It ignores a renumbered `file:line` citation (#172), and never denies on a shared path alone (#179). A create whose own `--title` or `--body` says `Replaces #N`, `Supersedes #N` or `Closes #N` is not denied over PR #N (#178). A command the shell lexer cannot balance, such as an apostrophe in a heredoc PR body, gets a report instead of a deny (#185). In the other direction, a PR listing exactly 100 files, which is all `gh` returns, now has its diff read, since the conflicting path can sit past that cut (#175). The trade is stated in the README: two branches that rewrite one function in hunks that do not touch now pass.

**[`ready` is harder to fool](https://github.com/karlkfi/claude-pr-sentinel/blob/v0.13.0/README.md#green-is-not-the-same-as-ready).** A re-run waiting in the Actions queue can have no check rows on the head, which left every remaining row green and the merge state `CLEAN`. In one measured case `ready` fired inside that window and the re-run then failed. A green poll now also counts the head's unfinished workflow runs, and `ready` waits for zero. A run stuck in the queue ends the watch in `timeout`, and if the run list cannot be read, `ready` still fires with a line saying so (#177). On `UNSTABLE`, `ready` no longer prints "All checks are green": it names both possible causes and gives `gh run list --commit <head>` to tell them apart (#187). A draft gets `ready_draft`, described above (#188). And a `gh pr checks` call that failed, through a dropped connection or an API error, is no longer read as a head with no checks. On a flaky network that misreading kept a green PR from ever reaching `ready`, and the watch timed out saying no check had run (#165).

**[`base_fixed` fires only when the base was broken where your branch started](https://github.com/karlkfi/claude-pr-sentinel/blob/v0.13.0/README.md#a-head-that-predates-the-bases-fix).** In 0.12.0, a failing PR whose head was merely behind a green base got `base_fixed`. On a busy repository that is almost every failing PR, so genuine failures lost their log excerpt and the session was told not to diagnose them. The watcher now also reads the base's run of the same workflow at your fork point, walking back through recent runs for a path-filtered workflow. Red there is `base_fixed`, and green is `check_failure`, naming that run. A `pull_request` run started after the green base run is `check_failure` by construction, because it tested your head merged into a base that already had the fix (#182).

**The Stop hook is right in more cases, in both directions.** It stopped blocking in three false cases: a PR stacked on a red parent, re-blocked once per watch budget for as long as the parent stayed red (#160); a declined inherited failure whose failed set grew as slower jobs finished red (#163); and sixteen PRs credited to a session because it wrote a script containing the text `gh pr create` through a heredoc (#167). It now blocks where it silently stood down before: the resumed-session and `gh pr merge`-in-a-heredoc cases in the banner above (#164, #168). In the Claude desktop app, the block now explains that a PR the app has bound is not a watched one unless its Auto-fix is on, and tells the session to launch the watcher despite the app's instruction not to poll CI (#169).

## Upgrading

**Nothing to do for most installs.** No removals, no renames, no new configuration. A plugin install carries everything.

**Two new event names, none removed or renamed.** The set goes from sixteen to eighteen: the terminal **`ready_draft`**, and the **`ready_draft_watching`** notice under `PR_SENTINEL_WATCH_UNTIL=closed`. The Stop hook treats `ready_draft` as a handoff, like `ready`, and `ready_draft_watching` as a notice. A session matching on `PR-SENTINEL EVENT:` headers gains two values and loses none, but a green draft that used to reach `ready` now arrives as `ready_draft`.

**Fewer `base_fixed` wakes, more `check_failure`.** A failing PR that is behind a green base now gets `check_failure`, with its log excerpt, unless the base was red at its fork point. `base_fixed` gains a line naming the base's run at the fork point.

**Some report text changed.** `ready` and `ready_watching` on `UNSTABLE` no longer say all checks are green. `ready` can add a line when the head's workflow runs could not be read, and `timeout` can say why `ready` was withheld or that the check reads failed. A reader parsing report lines should not rely on the old `UNSTABLE` wording.

**The overlap check wants git 2.38 or later** for its trial merge. On an older git, or when an open PR's head is not in your clone, the line ranges stand in for the merge: edits within six lines deny only where the changed lines touch with no unchanged line between them, and the denial says it was not trial-merged (#193).

**The overlap check denies less.** A clean trial merge is silent, so two rewrites of one function in hunks that do not touch are no longer caught. That is deliberate: in the denies whose outcome was recorded, every clean-merging one was overridden rather than folded.

## Deprecations

**Nothing is deprecated, and nothing user-facing was removed.** No configuration key, event name, report field, or script path went away this window.

## Trust boundary

**Two new `gh --json` fields, neither written by a person.** The watcher's `gh pr view` now reads `isDraft`, a boolean (#188). The overlap check's `gh pr list` now reads `headRefOid`, each open PR's head commit, to recognise a stack and to find a head to trial-merge (#174). `files` was already in that list at v0.12.0; #175 adds no field, and only fetches the diff of a PR whose `files` list stopped at 100. Neither list can reach `body`, `comments`, `reviews`, or `title`, and a new test fails the build if any field goes unnamed in `PRIVACY.md` (#180).

**New Actions reads in the watcher, each reduced on your machine.** On a poll where every check is green, the watcher counts the head's unfinished workflow runs (`actions/runs?head_sha=`), and the response reaches it only as that number (#177). To settle `base_fixed`, it reads the `compare` response's merge-base SHA alongside the `status` word, the base's run of the failing workflow at that commit, and when there is none, the workflow's 20 most recent completed base runs and up to five more `compare` reads; plus the `event` and age of this PR's own failing run (#182). Those responses also carry run names, commit messages and actors, and `gh`'s built-in query extracts only the fields `PRIVACY.md` names before anything reaches the watcher. Each fork-point read is taken once per head commit and green base run, and `PR_SENTINEL_BASE_CHECK=0` switches all of them off.

**The PreToolUse hook writes to disk for the first time.** The trial merge runs `git merge-tree --write-tree` on your clone, and git stores the merge's trees and blobs as unreferenced objects in your repository's object store until `git gc` removes them. It moves no ref, touches no working tree, and fetches nothing (#176).

**Three new local reads, none from GitHub.** The overlap check reads the create's own `--title` and `--body` from the command string, which is text you are about to publish, and never opens a `--body-file` (#178). The Stop hook notes whether the session called a tool named `mcp__ccd_pr__*`, from the name alone; that tool's result carries the PR title and is never read (#169). The PostToolUse hook's existing `git` reads now run in the repository the push runs in rather than only the session's directory (#183), and the overlap check's run in the checkout a `cd` earlier in the create's command lands in (#191). All of them are disclosed in `PRIVACY.md`.

**No security advisory accompanies this release**, and no dependency bumps: the plugin is stdlib Python and POSIX-ish bash, and depends on nothing but `gh`.
