Wake your session on CI failures and merge conflicts — no foreground polling, no comment-channel injection.

> [!NOTE]
> **The `dequeued` report no longer asserts the queue evicted the PR, and the Stop hook can now resolve a `gh pr create` whose URL never reached the transcript.** Both were cases where the plugin was confidently wrong: a human removing a PR from the merge queue got an eviction story, and a create that redirected its output left the backstop with nothing to hold the session to. Three smaller fixes stop the PostToolUse nudge firing on a `gh pr create` that opened no PR. No new configuration, no events added or removed, nothing renamed.

## Highlights

**[`dequeued` names who removed the PR, and only guesses a cause when that was the queue](https://github.com/karlkfi/claude-pr-sentinel/blob/v0.9.0/README.md#merge-queues).** Until this release every `dequeued` report told the same story — the queue evicted you, probably a sibling merge or a group reset. That story is wrong whenever a person removed the PR deliberately, which is not an edge case: GitHub rejects a push to a queued branch (`GH006`), so dequeueing is the documented way to update one. The report now carries a `Removed from queue by: <login> (bot|human)` line, and the prose follows it. `github-merge-queue` is a `Bot`, so the eviction wording and its usual causes stay. A person's login gets a report that claims no cause at all and points the session at the push that was waiting on the dequeue, rather than at a re-read of the checks. When the actor can't be read the report names **both** possibilities and asserts neither (#63).

**[The Stop backstop resolves a create whose PR URL the transcript never saw](https://github.com/karlkfi/claude-pr-sentinel/blob/v0.9.0/README.md#what-it-does).** A `gh pr create … > out.log` prints the URL to a file, so the session opens a PR and the backstop sees nothing to hold it to — the same blind spot that makes the nudge go quiet, hit twice by the same command. Two routes close it. The harness's own `pr-link` record now counts, but only one emitted inside that create's own tool call *and* naming a PR the transcript has not mentioned before; both narrowings are load-bearing, because the harness emits a `pr-link` for any PR the session merely *references* and re-emits an already-linked one after unrelated commands, which is the shape that produced false-positive blocks when a bare record was trusted. Failing that, the hook reads the file the create redirected to, resolving the path from the create's own command string — byte-capped, and ignored if the file predates the create, since log paths get reused and a failed create must not inherit the previous run's URL (#60).

**A cross-repo PR now gets a watcher pointed at the right repository.** The redirect route recovers the whole URL rather than a bare number, and the block message passes the URL straight into the launch command. That is what makes the backstop work for a `gh pr create` run against a repository other than the one the session is sitting in — the case the `pr-link` route cannot cover, because the harness only emits those records for the session's own repo.

**Three ways the nudge fired on a `gh pr create` that opened nothing.** `gh` reports an API failure as `HTTP 503: No server is currently available …`, which carries none of the strings in the failure blocklist, so an outage produced a nudge for a PR that does not exist (#54). A command the user cancelled mid-run was never checked for `interrupted` at all (#56). And `--help`, `--web`, and `--dry-run` all exit clean while opening nothing (#57). The last one is fixed by inverting the test rather than extending the blocklist: the create path now nudges only when the output names a PR URL.

## Upgrading

**No action required.** Nothing is removed, no configuration is added or renamed, and no watcher event is added or removed. The full event set is unchanged at twelve.

**Two additive changes to output shape.** A `dequeued` report gains a `Removed from queue by:` line after `Base branch:`, present only when the actor could be read. The Stop hook's block message may now carry a full PR URL in the launch command where it previously always carried a bare number; the watcher accepts either, so a copied command works the same way.

**One prose change worth knowing about if you match on it.** The `dequeued` report body now has three variants rather than one, and the Stop hook's dampening notice for `dequeued` says "removal" where it said "eviction". Anything reading these reports by `PR-SENTINEL EVENT:` or by field name is unaffected; anything matching the explanatory sentences verbatim is not.

**One behaviour change on the nudge.** A `gh pr create` whose output does not name a parseable `https://github.com/<owner>/<repo>/pull/<n>` no longer nudges — previously it nudged unless the output tripped the failure blocklist. This is the intended trade: no nudge for a PR that does not exist, at the cost of no nudge for the rare create that opened one and printed the URL in a shape the hook cannot read. A later push to the branch brings the nudge back, and the Stop backstop no longer depends on that same parse.

## Trust boundary

**One new GitHub read, and it stays on the metadata side of the line.** The watcher now asks for the actor on the most recent `REMOVED_FROM_MERGE_QUEUE_EVENT` — an actor `__typename` and a `login`, never the event's free-form text, and never the PR body, comments, reviews, or title. `last: 1` keeps it to a single node with no pagination, and the query is made once when `dequeued` is reported, not on every poll. The login is echoed back into the report, so it is accepted only when it matches `^[A-Za-z0-9-]+$`; anything else leaves both actor fields empty and produces the report that asserts no cause. A token that cannot run the query gets the same both-causes report rather than a guess.

**One new local file read, and its path never comes from tool output.** The Stop hook reads the file a `gh pr create` redirected to, and the path is parsed out of the create's own command string — model-authored, never tool output and never CI-log text. A target carrying `$` or a backtick is left alone rather than guessed at, `/dev/…` is skipped, the read is capped at 8 KiB, and nothing is extracted but a `github.com` PR URL. The hook still makes no network call, still inspects no process table, and still writes nothing.

**No security advisory accompanies this release.** The `gh --json` field list the watcher passes to `gh pr view` / `gh pr checks` is untouched, and `tests/test_watcher.py` still enforces that it can never reach the comment channel.
