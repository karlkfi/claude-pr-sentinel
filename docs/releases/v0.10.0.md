Wake your session on CI failures and merge conflicts — no foreground polling, no comment-channel injection.

> [!IMPORTANT]
> **A `gh pr create` on a branch that edits lines an open PR already changes is now denied, and that check is on by default.** It is the first and only part of the hooks that talks to GitHub — `gh pr list`, then `gh pr diff` for at most three PRs that already share a path. It reads code, never prose: no PR body, no comments, not even the title. Turn it off with `PR_SENTINEL_OVERLAP_ENABLED=false`, which also stops the two queries being made at all.

> [!NOTE]
> **The three hook scripts became one entry point.** `pr-sentinel-guard.py`, `pr-sentinel-hook.py`, and `pr-sentinel-stop-hook.py` are gone; every event now runs `scripts/pr-sentinel.py`, which dispatches to a handler. The bundled `hooks/hooks.json` is updated, so a normal plugin install needs nothing. Anyone who wired those paths into their own `settings.json` by hand must repoint them.

## Highlights

**[Two branches rewriting one function get caught at `gh pr create`, not at review](https://github.com/karlkfi/claude-pr-sentinel/blob/v0.10.0/README.md#overlapping-pull-requests).** Duplicated or mutually invalidating work is expensive to find in review, because by then both branches have been written and one of them is going to be thrown away. The check compares **line ranges, not filenames** — two branches touching one file is ordinary, sharing a function is the finding. Both sides are read from the diff's pre-image side, so ranges taken from a shared ancestor are numbered in that ancestor and comparable; edits within six lines meet, edits seven apart do not. The false-positive direction is the one that costs you, so a shared path with no shared range is silent. Every probe fails silent: no `gh`, no credentials, an unresolvable base ref, a rate-limited token, a slow call — each costs a missed catch, never a blocked create (#74).

**[Polling now tracks how long the checks have been running, instead of how many polls have been made](https://github.com/karlkfi/claude-pr-sentinel/blob/v0.10.0/README.md#how-often-it-polls).** A poll-count backoff widens on the wrong variable: ten minutes into any watch every poll sits at `MAX_INTERVAL`, whether CI has been running thirty seconds or thirty minutes. The interval is now `age ÷ PR_SENTINEL_POLL_AGE_DIVISOR`, floored at `PR_SENTINEL_INTERVAL` and capped at `PR_SENTINEL_MAX_INTERVAL` — at the defaults, a suite under five minutes old is polled every 30 seconds and one past fifty minutes every five (#75).

**A pending poll is also held inside the run's expected finish.** Age alone is loosest exactly when a long build is about to end: twenty-eight minutes into a thirty-minute run it would sleep another three. `PR_SENTINEL_POLL_CLAMP` measures how long the base branch's last **green** run of the same workflow took and lets no poll sleep past that mark, taking the longest where several workflows are pending. The estimate is weak evidence and is treated as such — a workflow the base has never run green yields nothing, and a run that has already outlasted its estimate falls back to the age rule rather than pinning the whole overrun to the 30-second floor. Two `gh api` reads per pending workflow, cached against the run they were measured for; `PR_SENTINEL_POLL_CLAMP=0` turns the clamp and the reads off together (#86).

**[An activity report says whether the nudge is actually landing](https://github.com/karlkfi/claude-pr-sentinel/blob/v0.10.0/README.md#activity-report).** `/pr-sentinel-friction-report` re-reads the transcripts Claude Code already wrote to your disk — no telemetry, no network call — and ranks four things: follow-through (nudged PRs that got a watcher), events by kind, foreground launches, and what the PreToolUse guard decided, split by branch. The guard reading is the one that needed new plumbing: an override makes the guard defer, and a defer is silence, so the override tally is recovered from the commands sessions ran rather than from anything the guard emitted. Read it against the deny count — an override tally near it means the escape hatch is doing the guard's job (#85, #98).

**A second watcher for a PR one is already watching is denied.** Stacked watchers wake the session once each for the same event and poll GitHub once each, and they compound: every wake asks for a fix and a push, and each push used to ask for another watcher. A running watcher re-reads the PR's head commit on every poll, so it already covers whatever was just pushed and a relaunch adds nothing. The deny names the background task id, so restarting a watch to reset its budget is one `TaskStop` and then the launch again, rather than a dead end (#70).

## Upgrading

**One thing to check, and only if you wired the hooks by hand.** The three hook script paths are gone, replaced by `scripts/pr-sentinel.py` for every event. A plugin install carries the corrected `hooks/hooks.json` and needs nothing; a hand-written `settings.json` entry naming the old paths will silently stop firing.

**The overlap deny is on by default and is new behaviour at `gh pr create`.** If you routinely open branches that overlap on purpose, three escapes exist and none is all-or-nothing: `PR_SENTINEL_OVERRIDE=<reason>` allows one create, `PR_SENTINEL_OVERLAP_IGNORE` takes comma-separated globs for the file every branch edits by construction, and `PR_SENTINEL_OVERLAP_ENABLED=false` switches the check and its two GitHub queries off entirely.

**Hook timeouts dropped from 10000 to 60 seconds.** The old value was read as seconds, so a wedged hook could hold a tool call for close to three hours. Nothing here takes more than a second or two in practice (#73).

**Five new configuration knobs, no removals and no renames.** `PR_SENTINEL_POLL_AGE_DIVISOR` and `PR_SENTINEL_POLL_CLAMP` for the pacing, and `PR_SENTINEL_OVERLAP_ENABLED`, `PR_SENTINEL_OVERLAP_IGNORE`, and `PR_SENTINEL_BASE_REF` for the overlap check. All are documented in the Configuration table, and `tests/test_wiring.py` now fails the build for a `PR_SENTINEL_*` var that is not.

**No watcher event added or removed.** The set is unchanged at twelve, and a session matching on `PR-SENTINEL EVENT:` headers or field names is unaffected. Two reports gained lines: `check_failure` now names the base run it was cleared against and that run's age, and the `conflict`, `behind`, and `dequeued` reports name the `--onto` form when the heal is a rebase.

## Deprecations

**Nothing is deprecated, and nothing user-facing was removed.** The three hook entry-point scripts were replaced rather than deprecated — there is no shim and no warning, because the file paths were never a supported surface for anything but `hooks/hooks.json`, which ships with the plugin. If that assumption is wrong for you, the banner above is the migration.

## Trust boundary

**The hooks talk to GitHub for the first time, in exactly one place.** The overlap check runs `gh pr list` for the open PRs and their paths, then `gh pr diff` for at most three that already share a path. It reads **code, never prose** — no PR body, no comments, and not even the PR title, which its author writes and which a denial would drop straight into the session's context. A denial names the PR number and the shared paths and points at `gh pr diff <N>` so you read the overlap yourself. `PR_SENTINEL_OVERLAP_ENABLED=false` stops the queries being made at all. Every other hook path is unchanged and still makes no network call.

**Two new watcher reads, both on the metadata side.** `actions/runs/{id}` for a single run and `actions/workflows/{id}/runs` for that workflow's latest run on the base branch — the poll clamp's duration estimate, and the base-failure lookup's evidence. Both are `gh api` reads of the repository's own Actions data, taken at most twice per pending workflow and cached.

**The `gh --json` field list is untouched**, and `tests/test_watcher.py` still enforces that it can never reach `body`, `comments`, `reviews`, or `title`. Two new gates joined it this window: a GraphQL read `PRIVACY.md` does not name now fails the build, and so does a component or local file read the policy does not disclose.

**No security advisory accompanies this release.** No dependency bumps either — the plugin is stdlib Python and POSIX-ish bash, and depends on nothing but `gh`.
