# A separated option value shifts what the hook reads as the remote

`classify_command` finds the remote and the refspecs by position over the
flag-stripped argv (`scripts/pr_sentinel_hook.py:207:            non_flags = [a for a in rest if not a.startswith('-')]`),
so a flag whose value is a separate word puts that value where the remote
should be and slides every refspec one place right. `-o ci.skip` is the shape
that turns up in practice — a release cut that skips CI.

Measured against `origin/main`'s hook (`c821c06`), in a repo where the joined
form is silent:

| Command | Classified |
|---|---|
| `git push origin refs/tags/v1.0` | `None` |
| `git push --receive-pack=/x/rp origin refs/tags/v1.0` | `None` |
| `git push -o ci.skip origin refs/tags/v1.0` | `git_push` |

So the tag rule (#34), the default-branch rule (#82) and the
filesystem-remote rule (#106) all read `ci.skip` as the remote and
`origin` as a refspec, and the push nudges. The failure is toward noise
rather than silence, which is why this is small: an extra nudge on a
release cut, not a missed PR.

The fix is to consume a separated value with the flag that takes it rather
than dropping every `-`-prefixed word. `-o` and `--push-option` are the ones
worth confirming against `git push --help`; `--repo` and `--exec` take a value
too and their separated forms are unverified here. Note `--force-with-lease`
and `--receive-pack` are already safe in their `=`-joined spellings and only
matter if git accepts them separated.

`tests/test_hook.py` has the fixtures to extend — the tag and default-branch
cases each already assert the joined form.
