# A timed-out probe makes the guard silent, and a test reads it as a crash

The overlap check runs every `git` and `gh` probe through one helper with a
five-second cap
(`scripts/pr_sentinel_overlap.py:42:PROBE_TIMEOUT = 5        # seconds, per subprocess`),
and that helper swallows `subprocess.SubprocessError`
(`scripts/pr_sentinel_overlap.py:83:        proc = subprocess.run(argv, cwd=cwd or None, stdout=subprocess.PIPE,`).
`subprocess.TimeoutExpired` is a `SubprocessError`, so a probe that runs long
returns `(None, '')` exactly as a probe that never ran does, `overlapping_prs`
returns `[]`, and the guard emits nothing.

Failing open is correct and deliberate — a machine with no `gh`, no
credentials, or an unresolvable base ref must not block a create. The defect is
that `tests/test_overlap.py` cannot tell that fail-open apart from a pass, so
under load the suite errors instead of reporting a verdict either way.

## What was observed

Measured 2026-09-10 on `feed38c` while cutting v0.11.1. A full `make check`
failed with one error:

```
ERROR: test_a_backgrounded_create_is_still_denied (test_overlap.GuardDeny...)
  File "tests/test_overlap.py", line 573, in deny_reason
    hso = json.loads(out)["hookSpecificOutput"]
json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)
```

`out` was the empty string: the guard had emitted nothing. Re-running the same
suite over the same tree passed 517/517, and CI passed the same commit on
Python 3.10 through 3.13, so the trigger is machine load rather than the tree.
Seven other Claude sessions were live on this host at the time, one of them
running a watcher.

The mechanism was then planted rather than inferred. Driving the guard through
the suite's own `Scenario`, with a `git` shim on `PATH` that sleeps six seconds
before exec'ing the real one:

- control, normal `PATH` — stdout begins
  `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "perm…`
- slow probe — stdout `''`, exit 0, and `json.loads` raises the identical
  `JSONDecodeError: Expecting value: line 1 column 1 (char 0)`

So one probe crossing the cap reproduces the failure exactly, deterministically.

Every test in `GuardDeny` routes through `deny_reason`
(`tests/test_overlap.py:573:        hso = json.loads(out)["hookSpecificOutput"]`),
so any of them can fail this way; which one lands is whichever probe happens to
be slow. `test_a_non_overlapping_create_is_silent` is worse — it asserts
silence, so a timed-out probe makes it pass for the wrong reason and nothing
reports it at all.

Q27 is the same trigger seen from the other side — the wall-clock budgets
themselves, and a second site in `test_watcher.py`. Its fix makes a timed-out
probe rare; this row is about the suite not noticing when one happens, so
neither row closes the other.

## Proposal

Candidates, not a prescription.

- **Make the assertion say which silence it got.** Have `deny_reason` fail with
  a named message on empty stdout — "the guard emitted nothing: a probe failed
  open" — rather than a `JSONDecodeError` from the JSON layer. Cheapest, and it
  turns a confusing error into a diagnosis, but it does not stop the flake.
- **Let the tests pin the cap.** Read `PROBE_TIMEOUT` from an env var the
  scenario sets high, so a loaded machine cannot trip it. Removes the flake;
  adds a knob whose only consumer is the suite, which needs a README
  Configuration row or a deliberate decision to keep it undocumented and
  test-only.
- **Assert the fail-open positively.** Give `GuardDeny` a case that plants a
  slow probe on purpose (the shim above) and asserts the guard stays silent and
  exits 0. That behaviour is load-bearing and currently has no test at all —
  the check's whole safety argument rests on it.

The first and third are complementary and neither changes shipped behaviour.
The second is the only one that actually removes the flake, and is the one
worth deciding on.

## Out of scope

Not the five-second cap itself. Whether five seconds is the right budget for a
probe on a loaded machine is a separate question about the shipped default;
this row is only about the suite being unable to distinguish a fail-open from
a pass.
