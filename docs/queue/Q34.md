# Name the repo in the watcher report so a wrong-repo watch is visible

The watcher passes its PR argument straight to `gh`
(`scripts/pr-sentinel-watch.sh:222:	gh pr view "$PR" \`), so a **bare number**
resolves against whichever directory the watcher was launched from. A session
working two repos at once — routine under parallel dispatch, or when a task in
one repo files a row in another — then watches whichever PR holds that number
in the repo it happens to be sitting in. Nothing errors: PR numbers are dense
and shared with issues, so the wrong PR almost always exists and answers just
as confidently, including `closed`/`MERGED`, which also tells the session to
stop watching.

The nudge paths mostly no longer produce a bare number — the PostToolUse hook
launches with the whole PR URL, and the Stop backstop does wherever any of its
four resolution routes recovered one. What is left is a number typed by hand, a
Stop block that resolved no URL, or a model that resolved a number itself, and
for those the report gives the reader nothing to check against:
`scripts/pr-sentinel-watch.sh:544:	echo "PR: ${PR}"` echoes the argument back.
Measured against 0.9.0, that read `PR: 15` for a PR in a repo the session had
never touched.

The fix is cheap because the watcher already holds the answer: every poll reads
the PR's canonical URL into `PR_URL`
(`scripts/pr-sentinel-watch.sh:885:		IFS=$'\t' read -r STATE MERGE BASE HEAD_SHA PR_URL <<<"$gh_state"`),
for the merge-queue GraphQL query. Print `${PR_URL:-$PR}` in `report_header`
instead, so every report names owner, repo and number, and a wrong-repo watch
is one glance rather than silent. The fallback matters: `emit_error` can fire
before the first successful fetch, when only the argument is known.

Two things to check while making it. The Stop hook keys PRs off the watcher's
**launch command**, not the report's `PR:` line, so the change should not reach
it — confirm that rather than assuming. And the report format is documented, so
the decision tables in `README.md` need a pass.
