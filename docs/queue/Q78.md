# The friction report finds no deny made since Claude Code 2.1.281

Claude Code now opens a denied call's error with `PreToolUse:<tool> hook error: ` ahead of the guard's reason.
The report's matcher is anchored at the reason, `scripts/friction-report.py:200:DENY_TEXT = re.compile(r'\A(?:Error:\s*)?pr-sentinel:\s')`, so it reads every such deny as an ordinary failed command.
Nothing errors: the report prints a deny count, and the count is too low.

## What was measured

2026-11-23, over every transcript under `~/.claude/projects/` on one machine, counting each `tool_use_id` once:

| Opening of the deny | Claude Code versions | Denies | Found by the report's `scan` |
| --- | --- | --- | --- |
| `pr-sentinel: ` | 2.1.219 to 2.1.275 | 91 | 91 |
| `PreToolUse:Bash hook error: pr-sentinel: ` | 2.1.281 to 2.1.330 | 191 | 0 |
| `PreToolUse:Monitor hook error: pr-sentinel: ` | 2.1.325 to 2.1.330 | 6 | 0 |

The report has found no deny in October or November 2026.
The versions are the lowest and highest seen with each opening, so the change sits somewhere in 2.1.276 to 2.1.281.

## Shape of the fix

Accept the optional `PreToolUse:<tool> hook error: ` ahead of the opener, for the old and the new form alike.
The sole test matcher for the opener convention is this same regex, so check what `tests/test_friction_report.py` relies on it for before loosening it.

The Monitor rows need a second change.
The guard speaks on a Monitor call as well as a Bash one, and `scan` joins a deny only to a `tool_use` named `Bash` (`scripts/friction-report.py:548:and b.get('name') == 'Bash'):`), while an allow is read only from `scripts/friction-report.py:351:att.get('hookName') != 'PreToolUse:Bash'`.
`guard_deny`'s docstring says the guard speaks only on Bash, which this makes false.
A Monitor launch has no `run_in_background` field, so adding it to the join must not count one as a foreground launch.

Filed from the Monitor-matcher PR, which fixed the guard and left the analyzer alone.
