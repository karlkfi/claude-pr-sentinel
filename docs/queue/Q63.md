# A push that pushes nothing still nudges

`git push --dry-run` reports what a push would do and sends nothing; `git push
--help` opens the manual page and does not push at all. Both classify as
`git_push` today, so the session is asked to launch a watcher on a branch that
never moved.

Measured 2026-09-19 by driving `classify_command` directly, in this worktree,
whose `origin` is a forge:

| Command | Classified |
|---|---|
| `git push --dry-run origin HEAD:refs/heads/x` | `git_push` |
| `git push --help` | `git_push` |

The `--help` case reproduced live in the same session: running `git push --help`
to read the option list drew a watcher nudge naming a pull request branch.

`--dry-run`, `-n` and `--help` are all flags, so none of them reaches
`non_flags`, which leaves `['push']` alone and sends the classifier down the
default-remote path as though the command were a bare `git push`.

Not Q14, which is about what a refspec-less push *targets*: a `--help` from a
feature branch resolves to that branch, is not the default branch, and nudges
under Q14's fix exactly as it does now. The fix here is a flag check ahead of
the ref work, alongside the `--delete` / `-d` / `--tags` line that already
suppresses the shapes that are not PR-babysitting.

The failure is toward noise rather than silence — an extra nudge on a command
that read a manual page. `--help` is the more annoying of the two, because
reaching for it is what a session does when it is *about* to push.
