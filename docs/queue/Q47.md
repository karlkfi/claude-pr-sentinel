# The release PR walk finds nothing on a squash-merged window

Step 2 of the release runbook enumerates the window's pull requests with
`git log --merges --oneline v<prev>..HEAD`, then puts the PR template's
security questions to each diff — the pass that catches a new GitHub read
`PRIVACY.md` does not name, or an env var that reaches a tag undocumented. The
runbook's own text records what skipping it cost at v0.9.0.

The repository now squash-merges, so that command matches nothing. Measured
cutting v0.11.0: `git log --merges --oneline v0.10.0..v0.11.0` printed **0
lines** against the window's 5 merged pull requests (#125-#129), where the same
command over `v0.9.0..v0.10.0` printed 36. Exit status is 0 either way, so the
silent zero reads exactly like "this window had no pull requests to walk" and
the security pre-flight is skipped with nothing to notice.

The failure shape is the one this repo already cares about elsewhere: an
instrument that cannot show you the opposite. A release cutter who trusts it
gets a clean answer from a query that can no longer match.

Fix is a command that enumerates squash merges too — the `(#NNN)` suffix
`git log --oneline v<prev>..HEAD` already carries is the cheapest source, and
`gh pr list --state merged --search 'merged:>=<date>'` is the cross-check. Have
it fail loudly, or state a count, rather than returning empty on no match.
