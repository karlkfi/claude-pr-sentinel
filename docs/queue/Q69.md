# A diff that could not be fetched still denies on a shared path

The overlap check's own rule is line ranges, not paths, and its module
docstring says a create blocked by a probe that could not run is not an
acceptable failure. When `gh pr diff` fails, though, `overlapping_prs` keeps
the PR as a hit on the shared path alone (`precise=False`), and the guard
denies on it. A failed probe therefore blocks the create, on the coarsest
signal the check has, which is the opposite of how every other probe here
fails.

## Measured

2026-11-01, installed pr-sentinel 0.12.0, one session-orchestrator run on a
Go repo with several worker sessions open at once. Two of the four overlap
denies in that run rested on no fetched diff at all:

| create | denied over | fetched |
|---|---|---|
| Q43, 21:01 PST | 4 PRs on `CLAUDE.md`, `tools/go.mod`, `tools/go.sum` | 0 of 4 |
| Q188, 21:56 PST | 1 PR on 10 paths | 0 of 1 |

Both denies read "shared path only, diff not fetched" for every entry, so the
first three `gh pr diff` calls of the Q43 create all failed and the fourth hit
`MAX_PR_DIFFS`. Re-run at 23:30 PST against the same five PRs, each
`gh pr diff` returned exit 0 in 0.86 to 0.95s, so why they failed during the
run is unmeasured. The 5s per-probe cap under concurrent sessions is the
likeliest cause and has not been confirmed. Each deny cost a human approval of
the override, because auto mode's classifier refuses the
`PR_SENTINEL_OVERRIDE=` prefix.

The Q188 deny is fixed separately: that branch was stacked on the PR it hit,
which the check now recognises without a declared `--base`. The Q43 deny is
this item.

## Shape of the fix

A path-only entry should not deny on its own. The choice left is what it does
instead: drop it (fail open, as the docstring promises), or list it in a deny
that some precise hit already justifies. The second keeps the information
without letting it decide anything, and is the recommended one.
`test_a_failed_diff_fetch_falls_back_to_the_shared_path` and
`test_only_three_diffs_are_fetched` in `tests/test_overlap.py` pin today's
behaviour and change with it.
