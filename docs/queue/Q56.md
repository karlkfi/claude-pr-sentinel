# A timed-out probe's label cannot say which git call blew the cap

When a probe in `tests/test_overlap.py` blows `PROBE_TIMEOUT`, the suite names
it in the failure message so a load flake is legible rather than mysterious.
The message is built from the first three tokens of the probe's argv, and for a
`git` probe those three tokens are always `git`, `-C`, and the repository root.
So every git probe in the module reports the same string, and the message that
exists to say *which* call was slow says "some git call in this repository".

The label is built at `tests/test_overlap.py:119`, inside the `capture` wrapper
the probe template installs
(`tests/test_overlap.py:106:PROBE = textwrap.dedent(`):

    timed_out.append(" ".join(argv[:3]))

and surfaced through
`tests/test_overlap.py:66:PROBE_TIMED_OUT = (`, whose `Timed out: %s` is the
only place a reader learns anything about the probe at all.

The collapse is a property of how `git` probes are spelled, not of the wrapper.
Every one of them goes through
`scripts/pr_sentinel_overlap.py:124:def git(root, *args):` (the `capture` call
is on `:126`) or
`scripts/pr_sentinel_overlap.py:136:def contains(root, rev):` (`:138`), and
both put `-C <root>` ahead of the subcommand. The operation — `rev-parse`,
`diff`, `symbolic-ref`, `merge-base` — sits at `argv[3]`, one token past the
slice.

The two `gh` probes,
`scripts/pr_sentinel_overlap.py:253:def open_prs(root):` and
`scripts/pr_sentinel_overlap.py:273:def pr_ranges(root, number):`, take no
`-C`, so their first three tokens already discriminate. That asymmetry is why
the blind spot stays hidden: the probes the suite actually times out are the
two that were already readable.

## Measured

Driven 2026-09-18 against `b3334a4`, wrapping
`scripts/pr_sentinel_overlap.py:96:def capture(argv, cwd, timeout=None):`
to record every argv reaching it through one `overlapping_prs` run, over a
synthetic repository with one open pull request and a stub `gh`:

    probes reaching capture: 7

    argv[:3]  ->  3 labels     argv[:4]  ->  6 labels
      x5  git -C <root>          x1  git -C <root> diff
      x1  gh pr list             x1  git -C <root> merge-base
      x1  gh pr diff             x1  git -C <root> rev-parse
                                 x2  git -C <root> symbolic-ref
                                 x1  gh pr list --state
                                 x1  gh pr diff 7

Five of the seven probes on that path share one label today. Widening the
slice by one token takes it to six labels over seven probes.

Counting probe *shapes* across the whole module rather than one code path,
there are seven git spellings — `rev-parse --verify` (`resolves`),
`rev-parse --show-toplevel` (`repo_root`), `symbolic-ref` twice (`base_ref`
and `current_branch`), `diff` (`diff_ranges`), `merge-base HEAD` (fork point)
and `merge-base --is-ancestor` (`contains`) — all sharing the single
`argv[:3]` label, against four under `argv[:4]`.

## Why the suite cannot surface it

Under a uniformly lowered cap, `gh pr list` is the first probe in the flow and
trips first every time, so the labels the suite produces are always the two
that already work. A worker drove the module at a 0.05s cap and got 27
failures — 20 `PROBE_TIMED_OUT`, 7 `GUARD_SILENT` — with every one of the
20 naming `gh pr list`, correctly. That figure is the worker's, reported
here rather than re-run.

The collision needs a git probe to blow a 5s cap while `gh pr list` does not,
which is the loaded-workstation case the flake rows are about and which no
instrument in the suite can construct. So the defect is not reachable by a
test that reproduces it — only by one that asserts the labels apart directly.

## Options

- **Widen to `argv[:4]`.** One token. `capture` already holds the whole argv,
  so it costs nothing, and it separates the four git operations while leaving
  `gh pr list --state` and `gh pr diff 7` readable — the latter arguably more
  useful than today's, since it names the pull request. Recommended.
- **Drop `-C <root>` and keep more of the tail.** Closes the residual below as
  well, at the cost of a label expression that has to know the shape of a git
  invocation, and of a long one for the `diff` probe, which carries six flags
  before its operands.
- **Join the whole argv.** Separates every probe, and puts an absolute
  repository path and `--src-prefix=a/ --dst-prefix=b/` into an assertion
  message. Rejected.

Whichever lands wants a test pinning the labels apart, because nothing else
can: the suite cannot reach the collision, so a regression to a narrower slice
would be invisible until the next real-load timeout. The assertion needs no
timeout to fire — it is a statement about the label expression over the
module's known probe spellings, so it runs in milliseconds and fails on a
slice change.

## The residual `argv[:4]` leaves

`base_ref` and `current_branch` both spell `git -C <root> symbolic-ref --short
--quiet <ref>`, differing only at the ref name. They share a label at
`argv[:4]` and at `argv[:5]` alike — the measurement above shows six labels
at both widths — so no slice separates them. Either accept it and say so in a
comment, or take the second option. Do not reach for `argv[:5]` expecting it
to help.
