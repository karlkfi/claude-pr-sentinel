# The friction report counts an overlap report as a defer

Since Q62, a `gh pr create` that shlex cannot lex, but whose line-by-line parse
still finds the create, gets an overlap **report** from the PreToolUse guard: a
`hookSpecificOutput` carrying `additionalContext` and no `permissionDecision`.
The friction report does not see these. `guard_decision` in
`scripts/friction-report.py:369:    if decision not in ('allow', 'deny'):` returns
None for any output without an allow or deny, so a report is tallied exactly
like a silent defer.

That leaves Q62's last point open. Q62 measured three inline
`PR_SENTINEL_OVERRIDE=` prefixes on 2026-09-19 that landed on creates the guard
had already deferred on, and those still read as overrides of a deny. The report
should now stop new ones from being written, and nothing here would show it.

## Shape of the fix

Have `guard_decision` recognise the report by its own opener (the
`could not be parsed strictly` sentence `build_report` writes) as a third
decision, `report`. Then split an override landing on a create the strict parse
rejects away from the deny overrides, so that count reads as friction caused by
the guard's former silence rather than by a deny. Cover both with a synthetic
transcript in `tests/test_friction_report.py`.

Filed from the Q62 PR, which shipped the report without touching the analyzer
(scope).
