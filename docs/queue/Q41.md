# A watcher launch whose PR argument abuts a terminator is invisible

`WATCH_ARG_RE` (`scripts/pr_sentinel_watchers.py:27`) captures the launch's PR
argument as `\S+`, so a bare number written against a terminator comes back
with it attached — and `pr_number` (`scripts/pr_sentinel_watchers.py:47`) then
resolves nothing:

    bash ".../pr-sentinel-watch.sh" 42; echo launched   ->  '42;'  ->  None

The launch is dropped from the shared scan entirely, which costs all three
readers at once: the Stop hook does not count it as ownership or as a live
watcher, the PostToolUse nudge asks for a second watcher on a PR already
covered, and the PreToolUse guard's duplicate deny never fires. Measured
2026-09-05 on the three shapes: `42;` resolves to `None`, `42` to `42`, and a
URL argument to its number either way — `PR_URL_RE.search` finds the URL inside
the token, so only the bare-number form is blind.

Narrow in practice: the launch line the hooks print ends at the argument, and
the redirected shape a session writes from habit puts a space before the
redirect. What reaches it is a session appending its own step —
`… watch.sh 42; echo launched`.

The fix is one character in the capture (`[^\s;&|<>]+`) plus a case per shape
in `tests/test_watchers.py`. Neighbour to `_watcher_redirect_path`
(`scripts/pr_sentinel_stop_hook.py`), which starts its segment scan at the
script name rather than after the argument for exactly this reason.
