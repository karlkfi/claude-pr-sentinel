# Four `open-question` rows name no route, which lint now notes

Refreshing the vendored `scripts/queue.py` to claude-skills `551d90d` brought
`question-route` with it (upstream `593ba42`): a row carrying `open-question`
has to say how the question gets answered, with a bolded `**Settles:**`,
`**Measure:**` or `**Ask:**` marker. Every row in this store predates the
convention, so all four that carry the label now draw a note:

```
queue: note: Q35.md carries open-question but names no route; say whether it
Settles from the repo, needs a Measure, or is an Ask for the maintainer
```

Q36, Q37 and Q40 draw the same line. `lint` still exits 0 — the class is
advisory — so the pre-commit gate and the CI backlog job stay green, and this
is noise on every run rather than a break.

The rows are not routeless in substance, only in form. Q37 already ends on a
numbered "the second is the open question" section naming what has to be
decided and against which knob; what it lacks is the marker a checker can read.
So the work is choosing the right one of the three per row and writing the
sentence, not deciding the questions:

- `**Settles:**` — answerable by reading this repo.
- `**Measure:**` — needs a probe run first.
- `**Ask:**` — the maintainer's call.

Picking the marker is a judgement about each question's evidence, which is why
this is its own item rather than part of the vendoring refresh.
