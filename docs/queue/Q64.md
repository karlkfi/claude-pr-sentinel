# The Stop hook's conclusion signal has no durable home

A PR is concluded, for the Stop backstop, when its watcher's terminal report
says so. That report lives in the harness's task output file, a temp file this
plugin neither owns nor can keep, and when it goes the conclusion goes with it.

The measured case is fixed: the report text is usually also in the transcript,
as the result of the Read or the `cat` that surfaced it, and the hook now
recovers it from there. What that cannot reach is a watcher whose report the
session never surfaced at all — the shape
`tests/test_stop_hook.py:924:    def test_concluded_via_direct_file_read_no_transcript_read(self):`
covers, which passes today only because the file is still on disk. Once it is
reaped that PR has no conclusion signal anywhere local, and the hook blocks the
stop over a PR that merged days ago.

## What produced this row

2026-09-24, a `karlkfi/claude-bouncer` session against pr-sentinel 0.11.1. The
block named PR #152 as open; it had been `MERGED` for 2d 23h. Its watcher had
reported `ready` and the session had `cat`-ed that report, but the task output
file was gone. PR #153, watched in the same session 46 minutes later and whose
file survived, was correctly suppressed — the difference between the two was
file existence and nothing else.

Not a tmp reaper on age: 206 task output files older than three days survived
on the same machine, the oldest 38 days. What removes them is unestablished,
and it does not need to be — the plugin cannot keep the file either way.

## What the answer costs

Giving the signal a durable home means the Stop hook writes, and
`PRIVACY.md:166:- Runs **entirely locally with no network access.** It blocks the end of a turn`
declares the opposite: the hook "makes NO network call, reads no process table,
writes nothing". That is a disclosed property, so trading it needs a reason, a
`PRIVACY.md` entry, and a cleanup story for whatever it writes. Q50 is the
neighbour worth reading first — the disclosure gates see reads and are blind to
writes, so nothing would catch an undisclosed one.

The alternative shapes, neither obviously better: ask GitHub for the PR state,
which costs a network round-trip on every turn end for a hook that fires
constantly and breaks the same declared property from the other side; or accept
the residual as rare enough to leave, which is what the measurement below is
for.

## The decision

**Measure:** how often a watcher's terminal report reaches no transcript at all
*and* its output file is gone. The local corpus under `~/.claude/projects/` can
answer it — `scripts/friction-report.py` already walks those transcripts for
launches and completions, so the join is the launch's output path against
`os.path.exists` plus a scan for any tool result carrying that path. A rate near
zero settles this as "leave it, the recovery pass is enough" and the row is
deleted; a rate that is not near zero is the argument for a durable record, and
sizes it.

Nothing about the residual's frequency is measured yet. The rank is provisional
on that.
