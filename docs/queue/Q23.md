# Assert every test suite is listed in CLAUDE.md

Nothing checks CLAUDE.md's Testing section against `tests/`, so it drifts
silently. Q20 was filed at four-listed-of-eight and had reached four-of-eleven
by the time it was worked, eleven days later. Both gaps were found by a human
reading the file, which is the only detector there is.

`tests/test_wiring.py` already has the shape:
`test_every_env_var_is_in_the_configuration_table` gates the README
Configuration table against the vars the scripts read. So this is one more test
beside it — glob `tests/test_*.py`, assert each is named in CLAUDE.md, and
assert the reverse so a deleted suite loses its line too. Both directions
matter: Q20's drift was additions going unlisted, and a removal leaving a stale
line is the same defect mirrored.

## The coupling question is settled

This row was filed noting that the test couples prose to the test tree, so
adding a suite stops being a one-file change, and asking whether that cost is
worth paying. It is, and the repo already decided it: the env-var gate above
imposes exactly this coupling on the README, in the same file, and has been
kept. Declining here would mean holding the Configuration table to a standard
CLAUDE.md is exempt from, for no stated reason.

Note also that the lead-in is part of the surface — Q20 had to change
"Four suites:" to "Eleven suites:" alongside the entries, and a count in prose
drifts the same way the list does. The assertion should cover it or the wording
should stop carrying a number.
