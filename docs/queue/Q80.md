# The friction report counts records a transcript repeats

A transcript can hold the same record twice, and a forked session's transcript can hold its parent's records.
`scripts/friction-report.py` counts each deny once per `tool_use_id` within a file, and nothing else it counts has that check.

Measured over every transcript on one machine, 2026-11-25:

| Count | Total | Repeated within one file | IDs also in a second file |
| --- | --- | --- | --- |
| launches, by `tool_use_id` | 6,629 | 26 | 59 |
| nudges, by `uuid` | 8,106 | 30 | 99 |

Events are deduplicated on the report body, so a partial read of a report counts beside the whole one.
178 of 4,617 events are a proper prefix of another with the same event and PR in the same session, which is a ceiling because two real runs could also read that way.

## Shape of the fix

Skip a `uuid` already seen, across the whole run rather than per file, before any record is dispatched.
That covers the first two columns at once and the fork copies of events with them.
Check the event count before and after: a session that reads another session's output file writes its own record, and `test_dedup_is_scoped_to_one_session` holds that those count separately.

The partial-read events need their own answer, and at under 4% may not be worth one.
