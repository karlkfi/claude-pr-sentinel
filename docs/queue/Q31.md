# De-duplicate `simple_commands` across the guard and the hook

`simple_commands` exists twice — `scripts/pr_sentinel_guard.py:184:def simple_commands(command):`
and `scripts/pr_sentinel_hook.py:90:def simple_commands(command):` — with the
same job and, until this week, the same defect.

The duplication is not a style complaint; it has already cost a real divergence
twice over. The newline defect (Q25) was fixed in the hook's copy by #78 and in
the guard's by #101, three PRs and about eighteen hours apart, and in between the
two copies tokenized the same command differently. The guard's copy is the one
behind both the foreground-poll deny and the `gh pr create` overlap deny, so for
that window the fix that existed did not protect the checks that needed it.

Nothing detects the split. Both copies pass their own suites, because each suite
exercises its own module, so divergence is invisible until someone reads both
files side by side.

## It gates Q30 in practice

[Q30](Q30.md) needs `simple_commands` to consume a heredoc body to its delimiter.
That fix lands in whichever copies exist when it is written, so doing Q30 first
means either writing the heredoc tracker twice or fixing one copy and leaving the
other divergent — which is this row's failure mode a third time. De-duplicating
first makes Q30 a single edit.

## Shape

The guard already imports siblings from its own directory —
`pr_sentinel_watchers` and `pr_sentinel_overlap` — so a shared
`scripts/pr_sentinel_tokenize.py` needs no new machinery, only the same
`sys.path` insert the guard already does. Move the function and its
`punctuation_chars`/`whitespace` setup there, import it from both, and keep the
callers' own classifiers where they are: the guard's `classify_poll` and
`is_pr_create` and the hook's `classify_command` are genuinely different jobs
over the same tokens.

Worth a test that asserts the two entry points agree on a shared corpus of
command shapes, so a future divergence fails rather than waits to be read.
