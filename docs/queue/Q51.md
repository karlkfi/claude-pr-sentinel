# A push's remote resolves in the session's directory, not the command's

`classify_command` decides whether a `git push` is PR work by resolving the
push's remote to a URL and asking whether it names a filesystem path — a scratch
or bare repo can hold no pull request, so those do not nudge (#106). The
resolution runs `git remote get-url --push <name>` in the `cwd` the hook is
handed, which is the **session's** working directory. A `cd` earlier in the same
command string does not move it: the hook has no `cd` tracking, so
`cd elsewhere && git push origin …` looks up `origin` in the repository the
session started in.

Measured 2026-09-18 on pr-sentinel 0.11.1 by driving the classifier directly
with one argv and two working directories:

| `cwd` | verdict |
|---|---|
| the scratch repo whose `origin` is `../remote.git` | `None` — correctly silent |
| this worktree, whose `origin` is `github.com:karlkfi/…` | `git_push` — nudges |

```
git push -q origin abc:refs/queue-ids/Q30
```

The observable that found it: a session building a throwaway repo under its
scratchpad to drive `alloc-queue-id.sh` got a watcher nudge naming a pull
request branch, for a push to a bare repo in a temp directory.

Both directions are wrong and the quiet one is worse. A filesystem-remote push
nudges whenever the session's own `origin` is a forge, which is the common case
— that is noise. The inverse suppresses a **real** PR push: a session whose own
repo has a filesystem `origin`, pushing a branch in a `cd`-ed sibling checkout,
is classified silent and the PR goes unwatched for its whole life, which is the
failure this plugin exists to prevent and it leaves no trace.

The same `cwd` reaches `_default_branch` and `_is_tag_ref`, so the release-cut
suppression is resolving branch and tag names against the wrong repository too —
a tag that exists in the session's repo and not the pushed one reads as a
release cut.

Not Q46, which is the neighbouring defect in the same function: there the remote
**token** is mis-picked out of argv by position, here the token is right and the
repository it is looked up in is wrong. Neither fix closes the other.

Route: workspace-guard tracks `cd` in a command string and resolves a literal
target, so the shape is established and a reader can compare against it. Whether
this hook should track `cd` at all, or instead refuse to classify a push it
cannot resolve confidently, is the call to make — the fail-open default today is
to nudge.
