# Seed the ID allocator from history so completed IDs are not reused

`refs/queue-ids/*` was seeded from the live store, so every ID a completed item used is claimable again. Q17 was filed in `c89cad6`, renumbered in `abfe5bb`, completed in `574bbf2`, and then handed out a second time by `./scripts/alloc-queue-id.sh` while this branch was filing Q19. That second claim is stranded rather than used.

Nothing catches it: `queue.py lint` and `queue.py claims` both read the current store, where a recycled ID is unique and claimed. Only history disagrees, which is where the cost lands — a bare `Q17` in a commit message or PR body no longer names one item, and [`maintaining-backlog.md`](../development/maintaining-backlog.md) says to reference items that way.

Backfill claims for every ID git history has used (`git log --diff-filter=D --name-only -- docs/queue/` plus the pre-migration `docs/STATUS.md` rows), so the allocator walks past them.
