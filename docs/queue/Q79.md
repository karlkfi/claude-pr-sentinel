# The friction report goes silent when a matcher stops matching

Every detector in `scripts/friction-report.py` is anchored on text something else writes: a hook's opener, the watcher's report header, the prefix Claude Code puts on a tool error.
When that text changes the detector matches nothing, and the report prints a low count or drops the section, which reads the same as nothing having happened.

It has happened twice.
Claude Code 2.1.281 prefixed denied calls, and the report found no deny in October or November 2026 (Q78).
The nudges began launching the watcher with a PR URL, and the report dropped every event from a launch that used one: a 7-day run with 345 launches printed no event section at all.

## Shape of the fix

Print the event section at zero when there were launches, rather than omitting it.
Beside each anchored count, print how many near misses it refused: an error result carrying `pr-sentinel: refusing` that no deny was read from, and an event header with no readable `PR:` line under it.
The second is not zero today: 218 headers in the local corpus on 2026-11-25, most often with a later field of the report on the next line, as a filtered read would leave it, so the number wants a baseline rather than a threshold.

Filed from the Q78 PR, which fixed both matchers and left the silence alone (scope).
