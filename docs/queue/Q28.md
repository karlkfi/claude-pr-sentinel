# `capture()` cannot tell a timed-out probe from one that never ran

`scripts/pr_sentinel_overlap.py:71`:

```python
def capture(argv, cwd, timeout=PROBE_TIMEOUT):
    """(exit status, stdout) for a subprocess, or (None, '') if it never ran."""
    try:
        proc = subprocess.run(..., timeout=timeout)
    except (OSError, ValueError, subprocess.SubprocessError):
        return None, ''
```

`subprocess.TimeoutExpired` subclasses `SubprocessError`, so a probe that ran
and blew its budget returns byte-identical `(None, '')` to one that never
launched. The docstring names only the second.

**The resulting behaviour is deliberate and documented** — README:149-151 lists
"a slow call" among the probes that "cost a missed catch, never a blocked
create". This row is not claiming an undisclosed fail-open. What is undisclosed
is that the two causes are indistinguishable to every caller:

- **To the tests.** The suite cannot assert on either, which is half of Q27.
- **To the transcript**, which is the sharper half. The overlap deny is the one
  guard branch that reaches the network, so it is the only one that can fail to
  *reach* a verdict rather than reach a negative one. Both outcomes emit
  nothing, and nothing is byte-identical to "checked, no overlap". So the guard
  can silently stop evaluating overlap and leave no record that it stopped.

That last point makes the activity report (Q15, #98) unable to separate "no
branch overlapped" from "the probe timed out on every create" — the distinction
is not in the data, so only the guard can record it. Fail-silent is right for
the *decision* and wrong for the *record*.

Fix: give a timeout a distinct return (or let `TimeoutExpired` reach a caller
that logs it), and correct the docstring with it.

Raised by the Q15 worker on #98 while reviewing Q27; the record half is theirs.
