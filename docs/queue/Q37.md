# Draft is an unnamed cause of the watcher BLOCKED report

`blocked_detail()` names two candidate causes and draft status is neither
(`scripts/pr-sentinel-watch.sh:754:	echo "check list cannot show is unsatisfied. The two usual causes:"`):
a required check that never registered, or an outstanding approval or
unresolved conversation. A draft PR reports `BLOCKED` too, so the report sends
the reader hunting for a missing gate that does not exist.

The API makes that structural rather than a quirk of one PR. `MergeStateStatus`
has no `DRAFT` value:

```
$ gh api graphql -f query='{ __type(name: "MergeStateStatus") { enumValues { name } } }'
DIRTY UNKNOWN BLOCKED BEHIND UNSTABLE HAS_HOOKS CLEAN
```

Draft therefore collapses into `BLOCKED`, and every draft PR that goes green
fires the event. The watcher cannot tell the difference because it never asks:
`scripts/pr-sentinel-watch.sh:223:		--json state,mergeStateStatus,baseRefName,headRefOid,url \`
carries no `isDraft`, and `draft` appears nowhere in the script.

Measured with a control rather than as an anecdote, on
`actions-gateway/github-actions-gateway`, 2026-08-25:

| PR | `isDraft` | `mergeStateStatus` | `reviewDecision` | `mergeable` |
|---|---|---|---|---|
| #1711 | false | `CLEAN` | `""` | `MERGEABLE` |
| #1721 | true | `BLOCKED` | `""` | `MERGEABLE` |

Same repo, same moment, byte-identical check sets on the two heads.
`reviewDecision` is empty on both, so an outstanding approval cannot explain the
difference; the check sets match, so a missing gate cannot either. `isDraft` is
the only varying input. Cost was three API calls ruling out phantom causes on a
PR that was fine. Re-checked while filing this: #1711 has merged since, #1721
still reads `isDraft: true`, `BLOCKED`, `reviewDecision: ""`.

`blocked` is still the right event. A draft genuinely cannot merge, so the
watcher is correct to refuse `ready` and hand back to a human, and the report is
correct to refuse to call the PR green. Only the advice is wrong. Don't add an
event, add the cause.

The fix is to put `isDraft` in the field list and name draft first when it is
true. It is a GitHub-controlled boolean rather than human-writable text, so it
does not cross the line CLAUDE.md draws at `body`/`comments`/`reviews`/`title`.
Three things move with it: `tests/test_watcher.py:1528` asserts the field-list
string verbatim, `PRIVACY.md:89` enumerates what the watcher reads, and the same
two-cause list is duplicated in prose at `README.md:260` and
`docs/DESIGN.md:415`.

Worth weighing while making it: a green draft is a common shape rather than an
exotic one, because flipping a PR to draft is the standard way to park
work-in-progress on a branch that would otherwise look mergeable. Under
`PR_SENTINEL_WATCH_UNTIL=closed` that produces a `blocked_watching` notice on
every such PR, which is a lot of misdirection for a state the session already
chose deliberately.
