# `ready` fires on a draft pull request

A draft PR whose checks go green gets the terminal `ready` report
(`scripts/pr-sentinel-watch.sh:719:	echo "All checks are green and the PR has no merge conflict. Nothing left to"`),
whose next action is "hand back to a human for merge review". A draft is not
available for merge review, and the readiness guard cannot see that it is one:
it tests the merge state alone
(`scripts/pr-sentinel-watch.sh:1068:				&& [[ "$MERGE" != "BLOCKED" && "$MERGE" != "UNKNOWN" ]]; then`),
and `mergeStateStatus` does not observe draft status.

Measured on this repo's own PR #111, holding every other input constant. Same
PR, same head SHA, base `main`, checks green, minutes apart, flipping only the
draft bit:

| `isDraft` | `mergeStateStatus` |
|---|---|
| false | `CLEAN` |
| true | `CLEAN` |

Then a watcher launched cold against that PR, `isDraft: true` throughout the
run, exited `PR-SENTINEL EVENT: ready`.

The field is blind rather than merely unread. `MergeStateStatus` has no `DRAFT`
value at all:

```
$ gh api graphql -f query='{ __type(name: "MergeStateStatus") { enumValues { name } } }'
DIRTY UNKNOWN BLOCKED BEHIND UNSTABLE HAS_HOOKS CLEAN
```

So no widening of the guard's denylist can reach this. That is the difference
from Q36, which is the same symptom from the opposite cause: `UNSTABLE` is a
value the denylist could name and does not, whereas draft is not a value at
all. The watcher would have to fetch `isDraft`, which
`scripts/pr-sentinel-watch.sh:223:		--json state,mergeStateStatus,baseRefName,headRefOid,url \`
does not.

The wrong sentence is the smaller half. `ready` is terminal and joins the Stop
backstop's concluded set
(`scripts/pr_sentinel_stop_hook.py:130:    r'PR-SENTINEL EVENT:\s*(?:ready|closed|blocked)(?![\w-])')`,
consumed at line 586), so the PR is treated as handed off and the backstop stops
blocking on it (`README.md:174`). A draft is the one shape where more pushes are
expected by definition — parking work-in-progress is what drafting is for — so
the watch ends exactly where babysitting still had a job.

Two pieces, and the second is the open question:

1. **Stop calling a draft ready.** Uncontroversial: the report should not tell a
   session to hand a draft back for merge review.
2. **Decide what fires instead.** Withholding `ready` outright walks into the
   trap `docs/DESIGN.md:466` already records for the `BLOCKED` case — the watch
   burns its budget and wakes on `timeout`, on a PR that is genuinely fine. The
   shape that avoids it exists: `notice_ready_watching` is already the
   non-terminal counterpart of `emit_ready`, so a green draft could take the
   notice and keep polling until it is undrafted or closed. Worth checking
   against `PR_SENTINEL_WATCH_UNTIL`, since that notice is currently the
   `closed`-mode path rather than a draft path.

Three things move with the field-list change: `tests/test_watcher.py:1528`
asserts the field-list string verbatim, `PRIVACY.md:89` enumerates what the
watcher reads, and the decision tables in `README.md` document the event.

`isDraft` is a GitHub-controlled boolean rather than human-writable text, so it
does not cross the line CLAUDE.md draws at `body`/`comments`/`reviews`/`title`.
