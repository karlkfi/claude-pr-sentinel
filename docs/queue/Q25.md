# A newline does not separate simple commands in the guard's tokenizer

`simple_commands` in `scripts/pr-sentinel-guard.py` documents itself as
splitting on "`&&`, `||`, `|`, `;`, `(`, `)`, newlines", and it does not split
on newlines: `shlex` consumes `\n` as whitespace before it can reach
`punctuation_chars`, so every line of a multi-line command lands in one group
and only the first line's leading word is ever read as a command word.

Measured 2026-08-19, loading the guard and calling it directly. Taken against
`main` at f6d140d and re-taken at 632f1f8, where `pr-sentinel-guard.py` is
byte-identical:

```
"git status; gh run watch 9"    classify_poll -> 'gh_run_watch'   (denied)
"git status\ngh run watch 9"    classify_poll -> None             (allowed)
```

A poll on the second line of a multi-line Bash call is the ordinary shape, not
a contrived one, so this is the poll deny's main evasion path and it is reached
by accident rather than on purpose.

It cuts the other way too, and this row was written by walking into it. A
`git commit -F -` whose message quotes a poll command is denied, because the
heredoc body is tokenized as shell rather than as the text the command writes:
the guard read the message's own example out of the body and refused the commit.
So the same tokenizer both misses a real poll on a second line and blocks a
commit that only talks about one.

The escape hatch inverts the same way: an inline `PR_SENTINEL_OVERRIDE=` prefix
on a second line is not honoured, because the assignment is no longer `argv[0]`.
The activity report counts that command as an override — it splits on newlines
itself — so the two disagree until this is fixed.

## The fix already exists, for the other copy

`simple_commands` is duplicated — once at
`scripts/pr-sentinel-guard.py:167:def simple_commands(command):` and once at
`scripts/pr-sentinel-hook.py:86:def simple_commands(command):`.

PR #78 (issue #76) fixes exactly this bug in the hook's copy, with the same
diagnosis, in one line inside the `shlex` setup:

```python
lex.whitespace = lex.whitespace.replace('\n', '')
```

It does not touch the guard's, and the guard's is the one behind the poll deny.
So the work is either applying that line to the guard's copy, with the
newline/semicolon pair above as its test, or de-duplicating the two — which is
arguably the real defect, since one of them has now been fixed alone.
