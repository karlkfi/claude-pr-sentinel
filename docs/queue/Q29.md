# Check the claims namespace against history in CI

`queue.py claims` asks whether the IDs a branch *adds* hold a claim. Nothing asks the converse — whether every ID history has spent still holds one. Q21 closed today's gap by backfilling eight claims, and [`maintaining-backlog.md`](../development/maintaining-backlog.md) now carries the check as a command someone has to remember to run, which is close to the state Q21 was filed about.

The check is one `comm` between history and `git ls-remote`, and CI's `backlog` job already has what it needs: `fetch-depth: 0` and a network. Two properties it has to keep. It fails closed on an unreadable remote, the way `claims --strict` does, because a namespace that could not be read is not a namespace that is complete. And it reads the left-hand list rather than trusting an empty result — a command that cannot see history prints the same empty output as a complete namespace, which is the failure mode that makes a bad check worse than none.

Worth deciding in the same pass whether `highest_local` should read the legacy `docs/STATUS.md` history by default. It does not today, which is why Q17 — filed into the old table and never a file under `docs/queue/` — sat above the floor and was handed out twice. With every spent ID claimed this is robustness rather than a defect: a floor that under-reports now exhausts `MAX_ATTEMPTS` and dies loudly instead of reissuing a used ID.
