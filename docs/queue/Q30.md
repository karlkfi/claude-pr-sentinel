# `simple_commands` reads heredoc body lines as commands

`simple_commands` in `scripts/pr-sentinel-guard.py` splits on newlines but does
not track heredocs, so each line of a heredoc body comes back as its own simple
command. A PR body that describes what an agent runs therefore reaches the
classifiers as a command:

```
cat > /tmp/b.md <<'EOF'
gh pr create is what an agent runs here
EOF
git status
```

`is_pr_create` returns true on that, and a body line leading with `gh run watch`
classifies as a foreground poll the same way. Measured 2026-08-19 against the
guard, once the newline separator was working — before that the whole body was
glued to the command after it and nothing in it was ever matched.

The direction is fail-closed: a spurious overlap or poll deny, never a missed
one. That is why it did not hold up the newline fix. What it costs is friction —
a session writing a PR body about `gh pr create` is denied and has to reach for
the override to get its own PR open.

The fix is for the tokenizer to consume a heredoc's body when it sees `<<` or
`<<-` and a delimiter, up to the line repeating that delimiter, instead of
emitting those lines as commands. `scripts/pr-sentinel-hook.py` carries its own
copy of this tokenizer and needs the same treatment; whether the two copies
should merge is a separate question and not settled here.
