# `simple_commands` reads heredoc body lines as commands

`simple_commands` in `scripts/pr-sentinel-guard.py` splits on newlines but does
not track heredocs, so each line of a heredoc body comes back as its own simple
command. A line that leads with a command this plugin classifies therefore
reaches `is_pr_create` and `classify_poll` as if it had been run:

```
cat > /tmp/b.md <<'EOF'
gh pr create was allowed here
EOF
git status
```

The trigger is narrow, and the bound matters more than the defect. Only a body
line whose *leading tokens* are the command matches, because both classifiers
key on a group's leading word. Measured 2026-08-19 against the guard, with
controls in both directions — a real `gh pr create` returns true and a body with
no mention returns false, so the probe could report either way:

| heredoc body line | `is_pr_create` |
|---|---|
| `gh pr create was allowed here` | true |
| `    gh pr create --fill` (indented code block) | true |
| the command alone inside a fenced block | true |
| `The gh pr create call was allowed.` | false |
| `- the gh pr create guard missed it` | false |
| `$ gh pr create --fill` | false |
| ``Run `gh pr create` to open it.`` | false |

So the exposure is a PR body quoting the bare command in a code block, not any
body that mentions it. Prose, bullets and `$`-prefixed transcript lines are
unaffected. A body line leading with `gh run watch` classifies as a foreground
poll on the same rule.

None of this was reachable before the newline separator worked: the whole
heredoc body was glued to the command after it, so nothing inside one was ever
matched.

The direction is fail-closed — a spurious overlap or poll deny, never a missed
one — which is why it did not hold up the newline fix. What it costs is
friction, bounded by the table above: a session whose PR body shows the command
in a code block is denied and has to reach for the override to open its own PR.

The fix is for the tokenizer to consume a heredoc's body when it sees `<<` or
`<<-` and a delimiter, up to the line repeating that delimiter, instead of
emitting those lines as commands. `scripts/pr-sentinel-hook.py` carries its own
copy of this tokenizer and needs the same treatment; whether the two copies
should merge is a separate question and not settled here.
