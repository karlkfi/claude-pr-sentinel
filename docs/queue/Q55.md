# Disclosure gates check a name appears, never that it describes the read

Four gates read `PRIVACY.md` and ask whether a component's reads appear in it.
Every one of them asks the same question — does this *name* occur in that
section — and none can ask whether the sentence around the name is true.
`tests/test_watcher.py:def undisclosed_rest_reads(script, privacy):` reduces a
`gh api` path to its literal segments and greps each one; its GraphQL sibling
`def undisclosed_reads(script, privacy):` does the same for traversed fields.
Both end in the same line: keep the names for which
`re.search(r"\b%s\b" % name, privacy, re.I)` finds nothing.

So a disclosure that names the right endpoint and describes it wrongly passes.
So does one where the name occurs in a sentence that is about something else
entirely.

This row's own reference above is an instance of the same shape, left in
deliberately. `queue.py lint`'s `CITATION_RE` requires `:(\d+)` and treats the
fragment as optional, so a reference carrying only a fragment is not checked —
not resolved, not drift-checked, not seen. Measured 2026-09-18: the same
reference to a file that does not exist draws a note with a line number and
silence without one. It resolves by hand (`tests/test_watcher.py`, line 2321 on
this branch) and nothing in the repository establishes that.

## What was measured

2026-09-18, on the branch adding the watcher's ancestry read. Two misses in one
afternoon, same shape both times, neither visible to any gate.

**The description was false and the gate was satisfied.** The first draft of the
new bullet read:

    No commit message, author, or file list is requested — only that one word.

The endpoint is REST `compare/{base}...{head}` and the watcher does read only
`.status`. But `-q` filters inside `gh`, on this machine, *after* the response
arrives. Measured against this repository, `ea81805...c4822ae`, seven commits:

```
105,840 bytes  commits[].commit.message, commits[].commit.author.name,
               files[].patch across 8 files
 79,368 bytes  the same with ?per_page=1, which trims only the commit array
```

Nothing surplus reaches the report, and the sentence was still false twice over:
those fields *are* requested, GitHub simply is not asked to filter. The gate saw
the segment `compare` in the section and passed.

**The inversion passed too, which is how narrow the check is.** Deleting the
substantive bullet alone left the gate green, because a one-line closing
sentence elsewhere in the same section also contained the word `compare`. It
goes red only when both mentions are removed. A single unrelated use of the word
anywhere in a component's section discharges the obligation for that endpoint
permanently.

## Why a gate is the wrong rung

The obvious fix is a fifth gate that checks accuracy, and it cannot be built. No
static check can compare an English sentence against what an HTTP response
carries, and one that tried would need the response, which means the gate makes
the call it is auditing.

What can be written down is the pattern both misses share: **an absolute
negative in a disclosure is a measurement.** "No X is requested", "reads
nothing", "writes nothing to disk", "the only component that does" — each is a
claim about everything that did not happen, which is the kind that cannot be
confirmed by looking at the code that does happen. Every one of them in this
repository's history has been either measured or wrong. The watcher section's
own "It writes nothing to disk" and the migration helper's "the only component
that does" were both false and both sat in the tree until a change in a
different component falsified them.

The candidate is therefore a convention in `CLAUDE.md`'s **Disclose every read**
paragraph and in `docs/development/`, not a test: a disclosure may state an
absolute negative only when it names what was measured to establish it. That is
checkable by a human reviewer in one pass and by nothing else.

## What is already covered

The four naming gates are worth keeping exactly as they are. They catch the
miss that actually recurs — an endpoint nobody remembered to mention at all,
which is how `undisclosed_reads` and `undisclosed_rest_reads` each came to
exist. This item is not a criticism of them and proposes no change to them.

The write-side gap is a separate item and is already filed; the two do not
overlap. That one is about a *direction* the gates do not look in. This one is
about the gates' one question being weaker than the sentence it appears to
license.

## Why this ranks low

Both misses were caught, by inverting rather than by a gate, and the disclosure
that shipped is accurate. The cost is paid by a future reader who takes an
absolute negative in `PRIVACY.md` at face value — which is the entire audience
that document has.
