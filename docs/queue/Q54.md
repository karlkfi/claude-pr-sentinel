# The citation regex drops a fragment that opens with whitespace

`CITATION_RE`'s fragment group opens with `\S`, so it cannot match a fragment
that starts with whitespace — `scripts/queue.py:93`, which reads
`r"(?::(\S[^\`\n]*)(?=\`))?")`. The comment above it states the reason
(`scripts/queue.py:84:# quoted text stops; that is also why the fragment may not open with a space,`).

That premise is false. `grep -n` emits the line as it is, indentation included:

    $ /usr/bin/grep -n 'failed_names="${failed_names' scripts/pr-sentinel-watch.sh
    1119:\t\t\t\t\t\t\tfailed_names="${failed_names:+$failed_names, }${name} (${bucket})"

So a citation into indented code parses as a bare `path:N` with the fragment
silently discarded — the optional group simply does not participate. Driven
against the store on 2026-09-18:

    CITATION_RE on Q53's citation -> path='scripts/pr-sentinel-watch.sh' line='1119' fragment=None

This row demonstrates it twice. The citation above to `scripts/queue.py:93`
carries no fragment precisely because that line is indented — writing one would
be silently discarded — while its neighbour at `:84` starts on `#` and is
checked normally.

The second demonstration is how this row was written. Both of its citations were
initially off by one, and the lint run caught **only** the `:84` one; the
indented `:93` went unreported, by the blindness this row documents. The row
filed beside it had its own citation into `pr-sentinel-watch.sh` land 8 lines
stale in the same session, also unreported, for the same reason.

A bare `path:N` is checkable only for **resolving**, so the row is reported only
if the file becomes shorter than the number. Drift is invisible at every
`--citation-window`, zero included, and `--strict stale-citation` cannot promote
a note that was never raised.

**Any indentation does it, not just tabs**, and a dropped fragment is
indistinguishable from one that was never written:

    tab-led     `exhibit:x.sh:1119:\t\t\tfailed_names="x"`  -> ('x.sh', '1119', None)
    space-led   `exhibit:x.py:10:    indented = 1`          -> ('x.py', '10',   None)
    visible     `exhibit:x.py:10:def foo():`                -> ('x.py', '10',   'def foo():')
    truly bare  `exhibit:x.py:10`                           -> ('x.py', '10',   None)

(The `exhibit:` prefix marks these as the row's subject rather than pointers it
relies on, so `lint` reads none of them. They are synthetic paths.)

Rows 2 and 4 are the finding. Python, YAML and Go citations are in the class
alongside bash.

## How much of this store it covers

Measured over the 23 items on `main` at `ea81805`, shipped regex beside a
permissive variant differing only in the `\S`:

    fragments the linter parses      32
    fragments it silently drops      13
    citations carrying none at all   12
    blind spot  13/45 = 29% of fragment-carrying citations

The 13 are not confined to one file — 8 cite `scripts/pr-sentinel-watch.sh`,
and the other 5 are Python: `scripts/pr_sentinel_stop_hook.py` twice,
`scripts/pr_sentinel_hook.py`, `scripts/pr_sentinel_overlap.py` and
`tests/test_overlap.py` once each. The bash concentration is real (62%) and is
explained by that file being both the most cited and the most tab-indented, but
the class reaches every language in the store.

One of the 13 is the `exhibit:stop_hook.py:130` citation whose absence from every lint
run is otherwise unexplained.

## Why it matters more than it looks

Most code worth citing is indented, and this repository's watcher is
tab-indented throughout, so the class covers a large share of every citation
into `scripts/pr-sentinel-watch.sh`. Two consequences:

- **A silent miss reads as a pass.** A row whose citation has rotted by
  hundreds of lines lints clean, and is indistinguishable from one that is
  correct.
- **The census in the row about citation drift is a floor, not a total.** That
  row measured 27 `stale-citation` notes over 8 items and reasoned about the
  signal-to-noise ratio from it. Citations in this class produced no notes at
  all, so they are absent from both the numerator and the denominator. Its
  argument is unaffected in direction; its numbers are undercounts.

## Options

- **Let the fragment open with whitespace** and strip it on both sides before
  comparing. Smallest change, and it makes the discarded fragments live — which
  will surface drift that has been accumulating unseen, so expect the note count
  to rise on the first run and do not read that as a regression.
- **Normalise leading whitespace out of the citation** when a row is written,
  so the stored fragment starts at the first non-space. Keeps the regex as it
  is and makes existing citations wrong until rewritten.
- **Require the fragment** rather than leaving it optional, so a citation that
  fails to parse one is an error instead of degrading quietly to `path:N`. The
  strongest signal and the most disruptive; it would reject citations that are
  deliberately line-only.

Whichever lands wants a fixture whose fragment is indented, asserted to be
parsed and to produce a drift note — that fixture fails today.
